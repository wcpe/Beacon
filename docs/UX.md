# Beacon 前端交互规范（UX）

> 活文档（入库于 `docs/`）：前端"怎么操作"的真源，与 `docs/PRD.md`（要什么）、`docs/ARCHITECTURE.md`（后端怎么建）并列。导航、页面职责、全局交互契约变更必须与代码同 PR 更新本文（见 `.claude/rules/doc-sync.md`）。单页交互细节写在该 FR 的 `docs/specs/<feature>.md` UX 段，本文只管全局与信息架构。
>
> 本文约束第二版页面（0.20.x 起）；Legacy 维护态页面（FR-138）冻结不改，不受本文约束。

## 1. 设计原则

- **任务导向**：页面为"运维要完成的动作"服务，不是后端数据表的映射。每个页面有**唯一职责**——一句话说不清职责的页面不准建（第一版页面失控的直接教训）。
- **高密度可操作**：1920x1080、浏览器 100% 缩放下一屏优先；面向 1000+ 子服，所有列表必须服务端搜索 / 筛选 / 分页或虚拟化，禁止一次性渲染不可操作的大列表（PRD §3 / NFR）。
- **看 → 做 → 验证闭环**：写操作页面必须让人看到"操作前影响、操作中进度、操作后结果"；错误脱敏后展示（ADR-0057），绝不静默。
- **先 mockup 后实现**：新页面或页面结构性大改，先出 demo 模式 mock 页面、评审拍板后才接真后端（门禁见 `.claude/rules/ux-spec.md`）。

**登录页 `/login`（FR-179，不属四大域，不进侧栏）**：全屏、无侧栏无页眉，独立于 AppShell 的公开页；唯一职责——用户名 / 口令登录换取令牌。除 demo 模式外，其余所有路由经路由守卫，无令牌一律重定向到此页（记住来访路径、登录后回跳）。视觉于 FR-179 阶段 A 经 mockup 评审门拍板（见 §5），阶段 B 接真鉴权仅换提交行为、不改视觉。

## 3. 角色 × 高频任务地图

页面存在的理由是承载下面这些任务；一个任务的完整闭环不应跨超过两个大域。

| 角色 | 高频任务 | 路径 |
|---|---|---|
| 运维管理员 | 接入新服：确认注册 → 分配区服 | `/servers`（待确认）→ `/zones` |
| 运维管理员 | 排查某服异常 | `/dashboard` 下钻 → `/servers` 详情 → `/service-analysis` / `/topology` |
| 运维管理员 | 发布插件 + 配置更新 | 交付：模板源选差异 → 变更单 → 审批 → 灰度批次 → 观察放行 |
| 运维管理员 | 出问题回滚 | 交付历史 → 整单回滚 → 观察 |
| 集群管理员 | 建 / 调大区小区、换区解绑 | `/zones`、`/servers` |
| 集群管理员 | namespace 隔离与互通信任 | `/namespaces` |
| 审计与安全人员 | 追溯一次操作 / 一条消息链路 | `/audits` ↔ `/commands` ↔ `/topology` 相互跳转 |
| 审计与安全人员 | payload 查看（填原因） | 消息明细 → 原因弹窗 → 记录入 `/audits` |
| 业务插件开发者 | **不使用后台**——只走本机 agent-api | 无页面；禁止为其新增后台页面 |

## 4. 全局交互契约

一处定义、所有页面引用，禁止各页各写一套。

- **列表范式**：服务端筛选 + 分页（或虚拟化）；默认列高密度；支持按 namespace / 大区 / 小区 / 状态过滤；批量操作用选择集 + 顶部操作条。
- **写操作范式**：影响预览 → 确认（高风险操作需二次确认 + 原因输入）→ 进度可见 → 结果明示；审批类操作进入待办而非即时生效。
- **错误展示**：按 ADR-0057 脱敏后 toast / 内联展示真因；异步任务失败落到可查询的状态字段，不无声消失。
- **状态设计**：每页必须处理空态（给引导动作）、加载（骨架屏）、错误（可重试）、超大数据量（截断 + 明示边界）四形态。
- **术语与 i18n**：界面用语与 PRD §8 术语表一致；文案全部走 i18n，禁止硬编码。
- **演示模式（FR-159）**：demo 构建（`vite build --mode demo`，dev server 恒开）既是对外演示也是**设计评审载体**；mock 数据必须覆盖空态 / 常规 / 超大量 / 异常四形态，评审时可切换。**门控**：常规 `vite build`（发布产物，控制面 go:embed 内嵌）不注册 mock、不产出 `mockServiceWorker.js`，以免拦截真实 `/admin/*`。
- **鉴权（FR-179）**：**登录**——`/login` 提交 `POST /admin/v1/auth/login`，成功把令牌存 localStorage（持久，刷新恢复），回跳来访页或首页；失败内联展示后端脱敏文案。**注入**——所有 `/admin/*` 请求统一带 `Authorization: Bearer <令牌>`（请求层单点注入）。**守卫**——受保护路由无令牌即跳 `/login`（记住来访路径）；**demo 模式免登录**，守卫放行不拦。**401**——任意 `/admin/*` 遇 `401` 即清令牌 + 跳 `/login`（后端无 refresh，不自动续期，过期需重新登录）。**登出**——页眉操作人区触发 `POST /admin/v1/auth/logout`（记审计）+ 清本地令牌 → `/login`。

## 5. 评审拍板记录（mockup 评审门）

> 依据 `.claude/rules/ux-spec.md` §3 与 ROADMAP P2 退出条件「所有页面拍板留档」。此后**页面结构性变更（改布局骨架 / 操作主流程 / 导航归属）必须重过评审门**并在此追加记录；小改（加按钮 / 列 / 字段）豁免。

### P2（0.22.x）全量 mock 管理台 —— 已拍板（2026-07-10）

用户经多轮浏览器评审（演示模式，四态可切换）对 §2 全部 17 页逐轮拍板通过。关键设计选型（选型 mockup 稿评审后即弃，不入库）：

- **视觉设计语言**：3 版运维总览 mockup（深色 NOC 状态墙 / 明亮现代 SaaS / 数据终端）中**选定「明亮现代专业 SaaS」（靛蓝品牌，Linear/Vercel 气质）**，固化为 `@beacon/ui` token 与核心组件质感，铺全站 17 页。
- **集群拓扑画法**：3 版 `/topology` 画法 mockup（放射网络图 / Sankey 流向图 / 机房平面图）中**选定「放射网络图」**——代理节点放射连小区聚合节点、大区淡色分区、节点健康着色、异常链路红色加粗直标失败率、数据流动画；画布支持缩放平移，超大量按小区→大区两级聚合防卡死。
- **全局交互定稿模式**（经 `/servers` `/zones` `/topology` 等逐页评审收敛，全站统一）：详情一律**非模态固定侧面板**（不遮罩 / 不模糊 / 不顶动布局）；列表页**主从 + 吸顶筛选 + 列表自区滚 + 吸底分页 + 行内前置关键信息**；模态仅保留创建与高风险确认；拖拽写操作过二次确认。
- **交付引导**：变更单「引导创建」五步向导 + 变更单全生命周期详情 + 交付历史追溯回滚，经评审确立为交付大域的核心交互。

## 6. 与其他文档的分工

- 本文：导航 IA、页面清单与唯一职责、角色任务地图、全局交互契约。
- `docs/specs/<feature>.md` UX 段：该页面的用户任务、进入路径、操作闭环、状态机细节。
- `docs/PRD.md`：要什么（FR 与验收）；`docs/ARCHITECTURE.md`：后端怎么建。
- 冲突时：先改本文（经确认），再动代码；禁止代码先行造成 IA 漂移。
