# 权限、安全、备份与维护

本文覆盖生产运行的最小安全与维护流程。示例中的地址、账号、口令和令牌均为占位符；凭据只能通过受控部署系统、环境变量或受限密钥库传递。

## 1. 访问控制

| 身份 | 适用场景 | 要点 |
| --- | --- | --- |
| 管理台登录 | 人工运维 | 管理员凭据换取会话令牌；所有写操作带操作者审计。 |
| API Key：`full` | 受控自动化写操作 | 仅给必须创建、发布或回滚的服务。 |
| API Key：`readonly` | 报表、监控和只读集成 | 写端点统一拒绝，遵循最小权限。 |
| Agent bootstrap token | Agent 防误连 | 不等同于管理员凭据，也不是公网安全边界。 |

API Key 明文仅会在创建或重置时显示一次。立即保存到受控密钥库；遗失时重置，旧密钥立即失效。不要把 Key、登录令牌、Agent token、数据库 DSN、完整公网地址或端口写进仓库、Wiki、截图、日志和工单。

管理台、管理 API、Prometheus 指标和数据库均应置于受控网络或反向代理之后。不要将管理端口直接公开到互联网；如需跨网络访问，使用组织认可的 HTTPS、网络准入和访问日志。

## 2. 配置与密钥卫生

1. 从 `config.example.yml` 或 `.env.example` 创建本机配置，真实 `.env` 不入库。
2. 将数据库口令、管理员口令、签名密钥、Agent token 和发布仓库凭据经环境变量或密钥管理系统注入。
3. 区分启动/安全项与可热更新的运维设置：改数据库、监听地址、认证或 token 后按部署流程重启；热设置在管理台变更并保留审计。
4. 轮换前先建立新凭据、灰度验证依赖方，再撤销旧凭据，避免一次性断开所有 Agent 或自动化。
5. 对配置预览、日志、审计导出和文件资产预览执行脱敏与最小可见原则。

## 3. 备份与恢复演练

备份不是只复制控制面二进制。至少覆盖：

- 主数据库，以及启用时的归档数据库；
- 控制面配置和由部署系统管理的密钥恢复材料；
- 每个 Agent 的 `plugins/Beacon*` 状态目录，包括身份、配置快照和传输账本；
- 已核验的控制面与 Agent GA 产品包及其 SHA-256 清单。

建议流程：先完成一致性数据库备份并校验可读；将备份加密后存放在独立受控位置；定期在隔离环境恢复数据库和一个 Agent 快照，验证能登录、身份仍被识别、历史审计可查且玩家链路不会因控制面恢复过程被阻断。恢复时不要把测试环境的 token 或地址带回生产。

热数据到期前应先归档、校验行数和抽样哈希，再清理热库。归档不可用时控制面可以降级运行，但必须告警并在恢复后处理积压；不要直接删除尚未验证归档的数据。

## 4. 升级、在线更新与回滚

1. 阅读目标 GA 的变更说明和兼容性要求，确认控制面、Agent 和业务 SDK 的版本矩阵。
2. 备份后在测试或小批服务器完成升级和玩家验收。
3. 仅使用已校验 SHA-256 的 GA 资产。RC 和开发构建不能作为自动更新来源。
4. 先升级控制面或按发布说明要求的顺序升级；Agent 按批替换 JAR 并保留其本地状态目录。
5. 观察健康、命令结果、配置交付和玩家落点；确认稳定后再推广。
6. 出现回归时停止推广，按已验证版本回滚控制面或相应批次。线上自替换依赖 Docker/systemd 等外部监督进程来完成异常重启和自动回退闭环。

不要通过删除数据库、清空 Agent 状态或强制改写版本文件来“修复”升级问题；这会丢失身份与审计证据。

## 5. 维护窗口检查表

- [ ] 备份已完成并验证，回滚版本和负责人明确。
- [ ] 管理员、API Key 和 Agent token 均按最小权限保存，未出现在操作记录中。
- [ ] 目标服务器已 drain 或已评估玩家影响。
- [ ] 发布后检查 Dashboard、Servers、命令观测、告警和审计。
- [ ] 更新结束后撤销临时权限，记录版本、时间和异常处理结果。
