# 配置、文件与交付

本文面向运维人员，说明如何用 Beacon v2 管理配置和文件，并把变更安全地交付到子服。

业务插件不应直接调用控制面 HTTP，应使用本机 Agent API，见 [业务插件 SDK](business-plugin-sdk.md)。

> **版本边界**：本文以 v2 为准。`/admin/v1` 的旧配置、文件树和覆盖集 API 仅为兼容参考，不能与 v2 的配置文件、文件资产、变更单混在一次发布中。

## 0. 五分钟上手

如果你只想「把一份文件推到几台服上」，按这个顺序做：

1. **确认目标**：在「服务器」页确认目标子服已接入、身份已确认、归属正确。
2. **准备内容**：
   - 改配置 → 在「配置中心」编辑并保存为新版本（见 §2）
   - 换文件 → 在一台样板上改好，然后让 Beacon 扫出差异（见 §3、§4）
3. **建变更单**：在「变更单」页选内容 + 选目标 + 看影响面（见 §4）
4. **提交并灰度**：提交后按批次推进，每批看观察窗再放下一批（见 §5）
5. **出问题就回滚**：整单回滚或只回滚指定子服（见 §7）

新手先读 §1 理解三类对象的关系，再动手。

## 1. 三类对象：先弄清你在改什么

| 对象 | 它是什么 | 会不会动到线上 |
| --- | --- | --- |
| **配置文件** | 受五层作用域覆盖的文本配置，有版本历史 | 不会。改配置只是产生新版本 |
| **文件资产** | Agent 扫描上报的本机文件清单（只读事实） | 不会。清单不代表文件已被托管 |
| **变更单** | 把配置版本或文件差异真正投放到服务器的发布单元 | **会**。这是唯一会写入目标服的入口 |

一句话记忆：**配置中心管"改什么"，文件资产管"现在是什么样"，变更单管"什么时候推到哪"。**

### 作用域与覆盖

配置的作用域从宽到窄：`namespace → BCCluster → Region → Zone → server`。

越具体的层覆盖越宽泛的层。改配置前先用「有效预览」看清合并结果，再建交付单。

## 2. 改配置文件 {#configs}

1. 在「配置中心」选择命名空间，新建或打开目标配置文件。
2. **选对作用域**：全局默认放 namespace；只针对某个小区或单服的差异放 Zone 或 server，避免复制整份文件。
3. 编辑前先看版本历史与 diff；保存时写好变更说明（用于日后追溯）。
4. **跑格式/结构校验**。校验不通过就先改内容，不要靠跳过校验发出去。
5. 在「有效预览」选一台真实目标服，核对：合并后的内容、每个键来自哪一层、有没有被删除的键。
6. 想撤销尚未交付的版本，用该文件的版本回退；**已交付的**要用变更单回滚，不要手工去目标服改文件。

> 敏感值不要写进截图、备注、工单或本文档。需要存敏感配置时，先确认控制面已按部署要求配置静态加密与密钥管理。

## 3. 查看文件资产 {#assets}

Agent 按本地 `assets.enabled` 与扫描周期上报 plugins 目录及服务器根目录的文件清单，用于盘点、跨服比对，以及发布前确认事实。

1. 在「文件资产」按子服、路径、扩展名筛选。**先看扫描时间**，过期就触发重新扫描再用。
2. 用「内容预览」查看文件正文、「跨服比对」看同一路径在各服的哈希分组、「两侧差异」对比两台服的具体差异。
3. 文件正文是**直接读取**的：点查看即返回内容，不需要申请审批。每次读取都会记录审计（审计只记谁在何时读了哪台服的哪个路径，**不保存文件内容**）。
4. 需要纳管的现存文件，走受控导入或审核流程生成文件差异；不要在多台机器上手工复制后假定内容一致。
5. 第三方插件的覆盖或重载只能通过变更单。Agent 本地 `override.command-whitelist` 为空时不会执行任何重载命令——**不要为了方便放宽白名单**。

> 文件资产索引是只读事实，不等于文件已被 Beacon 托管。只有当变更单明确包含该文件差异时，才会写入目标 Agent。

**敏感规则**：命中 glob 的文件标记为敏感。规则本身在「文件资产 → 敏感路径规则」维护；修改规则是高风险设置，需要审批。

## 4. 创建变更单 {#changes}

**一张变更单只做一件可回滚的事**。例如「给某个 Zone 更新大厅配置」或「向一批测试服发布同一插件」。不要在一张单里混入互不相关的改动——出问题时无法干净回滚。

1. **选内容**：加入已冻结的配置版本，和/或已审核的文件差异。
   - 只有文件：需要先指定一台**模板源服务器**（已手工装好新版并验证过的样板），系统扫描它与线上标准的差异作为载荷。
   - 只有配置：直接从配置中心选版本。
   - 两者都要：绑在同一单里，一起审批、一起灰度、一起回滚。
2. **选目标**：按 namespace / BCCluster / Region / Zone / server 或明确名单。系统会再次校验不会跨 namespace。
   - 目标只包含**已分配归属且身份已绑定**的后端子服；未分配的裸服不会出现在候选里。
   - 模板源本身会自动从目标中排除（它已经是基准，不需要被覆盖）。
3. **看影响面**：执行差异扫描与影响预览，确认目标台数、文件清单、覆盖关系、是否需要重启。
4. **提交审批**：提交后进入待审批。审批前可撤回；被拒绝后修订内容再重新提交。

## 5. 执行与观察 {#rollout}

1. 启动交付后，在变更单的事件流里跟踪每个目标的下载、应用与生效状态。
2. **生效判定**：
   - `仅推送`：文件推送到位，等子服下次自然重启生效。最保守，不打断在线玩家。
   - `热重载`：必须等到 Agent 的成功回执才算生效。涉及 jar 时会有额外风险提示。
   - `重启`：以服务心跳恢复为生效依据。
3. **超时或失败的目标不算成功**。离线的服会一直挂起到超时窗口结束，然后记为失败。
4. **观察窗**：每批推进后检查健康分、TPS、玩家数、告警。确认无异常再放下一批；有问题立即停止后续批次。

> 批次越小、范围越窄，出事波及面越小。首次上线建议用金丝雀节奏（约 10% / 30% / 60%）。

## 6. 审批：哪些要、哪些不要 {#approval}

**不是所有操作都要审批。** 判断标准是「能不能撤销、会不会造成不可逆损失」。

| 需要审批 | 直接执行 |
| --- | --- |
| 删除命名空间 / 集群 / 大区 / 小区 / 配置文件 / 变更单 | 查询、列表、详情等所有只读操作 |
| 凭据类：新建或重置 API 密钥、MCP 客户端、token 轮换、信任授予 | 创建类：新建配置版本、创建变更单草稿 |
| 系统更新、回滚、高影响设置 | **文件正文 / 日志 / 目录浏览 / 消息内容查看** |
| 拓扑迁移：服务器分配、换区、大厅归属迁移 | 变更单的暂停、撤回、取消（止损方向） |
| 身份启停、解绑、重新放行 | 配置实时校验 |
| 变更单审批、回滚、永久清除、批量导入 | 文件同步任务的启动与恢复（可随时终止） |

**关于内容读取**：查看文件正文、日志、目录、消息内容**不需要审批**，点开即读。这是有意的设计——这类操作高频且只读，加审批会严重阻碍日常排障。**审计照常记录**每次读取的主体、时间、目标路径与结果，但不保存正文。

**审批的实际价值**（即使只有一个账号）：

1. **不可逆操作的强制停顿**：删除、迁移、凭据变更前必须停一次，避免手滑。
2. **完整审计链**：谁、何时、为什么、当时的影响快照、执行结果。
3. **机器主体隔离**：API 密钥与 MCP 客户端**只能发起申请，不能批准**。这条边界无论多少人都成立。

审批申请固定 24 小时过期。申请内容创建后不可修改，状态变化全程留痕。

## 7. 回滚 {#rollback}

| 场景 | 用什么 |
| --- | --- |
| 整单退回 | 变更单详情 → 整单回滚。所有目标退回原版本 |
| 只有几台出问题 | 目标状态墙 → 勾选那几台 → 目标级子集回滚 |
| 配置还没交付过 | 配置详情 → 版本回退（只是产生新版本，不动线上） |

回滚本身也走审批并记录审计。回滚前系统会提示「哪些目标不可文件回滚」（例如从未成功推送过的目标没有备份）。

## 8. 交付前后验收清单

- [ ] 目标都在预期 namespace，身份已确认、在线、有近期健康数据
- [ ] 已看过有效配置与影响面，没有意外覆盖，没有敏感文件泄露
- [ ] 交付策略、批次范围、生效方式、回滚负责人已明确
- [ ] 每个目标都有终态；失败、超时、跳过项都已解释
- [ ] 观察窗内健康、日志、命令结果与业务验收都正常

## 9. 常见失败处理

| 现象 | 先做什么 |
| --- | --- |
| 有效预览与预期不同 | 检查五层作用域、版本与删除标记；修正来源层后重新冻结 |
| 目标长期未生效 | 看命令观测与 Agent 本地 `/beacon status`；确认热重载回执或重启后心跳 |
| 某批失败、其余成功 | 暂停推广，导出失败目标与错误摘要；先回滚受影响批次，再修正重发 |
| Agent 拒绝重载 | 核对本地白名单与命令安全规则；不要扩大任意命令权限来绕过 |
| 候选里找不到某台服 | 确认它已分配归属、是后端子服、身份已绑定；未分配的裸服不会出现 |

## 10. 对象状态口径 {#history}

- **配置版本**：一旦冻结即不可变，所有修改都产生新版本。已交付的变更只能用变更单回滚，不能靠覆盖旧版本"修复"。
- **文件资产**：索引是只读的扫描事实。扫描过期时先重新扫描再决策；索引本身不代表文件已受托管。
- **变更单**：按批次推进，每个目标必须落到终态（成功 / 失败 / 跳过）。失败与超时不计入成功；热重载以 Agent 成功回执为准，重启以心跳恢复为准。

更多症状分流见 [排障手册](troubleshooting.md)。
