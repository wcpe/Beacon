# 排障手册

先保护玩家，再收集证据，最后做最小的可逆操作。不要为排障直接改数据库、复制 identity 文件、泄露令牌，或在生产环境反复重启全部 BC/子服。

> **版本边界**：以下以 v2 控制面和 Agent 行为为准。遇到旧 `/admin/v1`、v1 Agent 接口或 Redis 消息字段时，仅按兼容路径查阅旧文档；新问题不要回退设计到 Redis 或业务插件直连 HTTP。

## 1. 首先收集什么

1. 记录发生时间、namespace、服务器 ID、角色、用户影响和最近变更单/改派/更新。
2. 查看 Dashboard 与 Servers：健康等级、原因、最后心跳、是否 drain/offline、身份状态。
3. 查看命令观测：命令类型、状态、年龄和结果摘要。
4. 查看审计和告警事件，建立“谁做了什么—何时出现异常”的时间线。
5. 在受影响节点执行 `/beacon status`；BC 还可执行 `/beacon servers [page]` 和 `/beacon server <serverId>` 查看受管目录。

收集时对 token、口令、API Key、数据库 DSN、玩家隐私和完整公网地址脱敏。

## 2. 症状速查

| 症状 | 可能原因 | 首选处理 |
| --- | --- | --- |
| Agent 一直 pending | token/endpoint 错、身份未审批、控制面不可达 | 核对最小引导配置和网络；在待确认列表核对角色/端点后分配 serverId 并批准。 |
| Agent active 但不健康 | 心跳/指标未上报、时钟或资源异常 | 看健康原因和 Agent 日志；先恢复服务资源与网络，再考虑重连。 |
| 玩家不能首次进服 | BC listener、LobbyCluster 候选或目录异常 | 确认 BC listener，检查大厅成员在线/可调度和 BC `/beacon servers`；不要把玩家静默导向普通游戏服。 |
| 调度无候选 | Zone 错、全部 drain/offline/unhealthy/满载 | 由 trace 查看排除原因；修复归属或容量，必要时有序取消维护状态。 |
| 调度显示本地降级 | 控制面短暂不可达或候选快照陈旧 | 玩家可继续使用快照；排查控制面连通性、DNS/反向代理和服务健康。 |
| 配置未生效 | 作用域覆盖、版本未入变更单、命令未回执 | 看有效预览、变更单目标与命令状态；不要在目标机手改文件掩盖问题。 |
| 交付卡住/失败 | Agent 离线、命令过期、下载或重载失败 | 暂停后续批次，查看错误摘要和 `/beacon status`，修复后对失败目标重试或回滚。 |
| 文件资产找不到/过期 | Agent 扫描关闭、扫描尚未完成或权限不足 | 查看扫描状态；在允许范围内请求重扫并核对本地路径权限。 |
| API 返回 401/403 | 凭据失效或 readonly 越权 | 区分认证失败(401)和权限不足(403)；轮换/申请正确角色，勿共享管理员凭据。 |
| 告警持续出现 | 根因未恢复或事件未处理 | 从告警跳到服务器、命令和审计；确认修复后再关闭/确认事件。 |

## 3. 控制面不可用

1. 确认进程监督状态、监听端口、数据库连接和反向代理健康。
2. 检查近期在线更新、配置变更和系统告警；保留日志与版本信息。
3. 不要急于重启所有 Agent。已有本地快照的 Agent 应继续 fail-static；新审批、拓扑变更和交付暂缓。
4. 控制面恢复后验证 Agent 自动重连、身份 active、候选刷新和本地降级决策补报，再恢复管理操作。

## 4. Agent、BC 与大厅

Agent 的本地配置只应含 endpoint 和 bootstrap token 等出生信息；namespace、serverId、Zone、地址和大厅归属由控制面权威分配。不要从另一台服复制 Agent 状态目录。

BC 问题按以下顺序检查：原生 Bungee listener 是否存在并可达；Agent 是否上报全部 listener；BC 所属 BCCluster 是否正确；全局大厅成员是否属于唯一 LobbyCluster、在线且可调度；受管目录是否成功同步。业务切服、管理员强制切服和普通 fallback 不应被“首次大厅落脚”逻辑错误拦截。

## 5. 何时回滚或升级处理

以下情况优先停止推广或回滚：配置影响面错误、批量交付持续失败、升级后健康持续恶化、首次落脚错误或出现数据/权限风险。回滚前保存变更单、命令、审计和健康快照证据；仅回滚明确受影响的版本或批次。

若怀疑版本缺陷，确认正在使用 GA 还是 RC/开发构建、核验资产 SHA-256，并按受控升级流程恢复到上一个已验证 GA。不要清空数据库或 Agent 快照来获得“干净状态”。

## 6. 升级支持时应附上的材料

- 脱敏后的时间线、namespace、serverId、Agent/控制面版本和部署方式；
- 健康原因、调度 trace ID、命令 ID、变更单 ID、相关审计和告警 ID；
- 最小复现步骤，以及是否在控制面断开时仍可复现；
- 已做的可逆操作及其结果。

更多部署、真实 Agent 验收和版本回滚流程见 [运维手册](../OPERATIONS.md)；全局大厅专项见 [全局大厅与 BC 接入操作手册](global-lobby-operations.md)。
