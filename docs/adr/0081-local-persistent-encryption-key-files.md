# ADR-0081：控制面加密密钥使用本地持久文件

**状态**：已接受（2026-08-03；取代 [ADR-0018](0018-config-encryption-at-rest.md) 的环境变量密钥来源）

## 背景

敏感配置的 AES-256-GCM 密钥原先仅从环境变量读取。当前控制面以单进程、单机优先部署，凭据审批还需要在审批成功后一次性兑换临时密文。手工维护环境变量会增加首次部署成本，也不能为本地持久数据提供自然的同目录备份边界。

## 决策

1. 控制面所有 at-rest 加密密钥统一只从本地持久密钥文件读取，不读取加密密钥环境变量。
2. 首次启动安全生成随机 32 字节密钥，使用独占创建写入控制面数据目录同级 `secrets/`；SQLite 使用数据库文件同级目录，非 SQLite 使用控制面当前工作目录。
3. 敏感配置与审批凭据分别使用独立密钥文件，避免跨域复用。
4. 密钥文件及目录使用最小权限；读取、创建、权限或内容校验失败时控制面 fail-closed 拒绝启动。密钥不入库、不入仓、不进日志、审计或 API 响应。
5. 密钥文件必须与控制面数据一同备份。丢失密钥文件后不尝试自动覆盖旧文件或恢复旧密文，避免把不可解密数据误当新数据。

## 理由

- 单机部署无需人工注入环境变量，首次启动即可安全建立稳定密钥。
- 密钥与其加密的数据保持同一持久化与备份边界，运维责任清晰。
- 分离文件避免敏感配置与审批凭据共享同一加密域。

## 后果

- `BEACON_CONFIG_ENCRYPTION_KEY` 不再被读取；部署不应再配置任何 at-rest 加密密钥环境变量。
- 多实例或容器化部署不能让各实例独立生成密钥；需要共享持久卷或另立 ADR 决定集中式密钥管理。
- 算法、密文格式、仓库层加解密与数据面明文下发保持 ADR-0018 的既有结论。

## 备选方案

- 环境变量：适合由外部 Secret 管理器注入的多实例部署，但增加当前单机部署的人工配置成本。暂不采用。
- KMS 或信封加密：超出单机控制面的实际需要，暂不引入。
