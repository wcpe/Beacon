# ADR-0086：agent 对业务插件开放「节点自声明」的窄写入面（在只读边界内）

**状态**：已接受（决策部分；其中决策 4 的「控制面只存不判：声明不进入调度决策」一条已被 [ADR-0087](0087-scheduling-admission-scope-over-self-declared-labels.md) 取代——自声明标签进入调度准入判定，仍不进健康打分、候选排序与 `?tag.*=` 过滤真源）；实现并入 FR-243，待排期

## 背景

现状是**「只读门面 + 一次性自报」**：

- `.claude/rules/architecture-invariants.md` §1 锁定：**agent 对业务插件只读暴露 API，不开放改配置 / 改 zone 的旁路**；`BeaconAgent` 类注释亦写明「MVP 只读不写」。
- 节点事实的**上报通道已存在且工程化完备**：`POST /beacon/v1/agent/data-plane/attach`（注册，携 `capacity` / `weight` / `metadata`）、`/heartbeat`、`/report`、`/beacon/v2/agent/metrics/report` 等，具备单飞门、代标识、退避与 fail-static。
- 但**声明类字段只在注册那一刻写入一次**：`AgentIdentity` 的 `capacity` / `weight` / `metadata` 在 core 里是 `val`；bukkit 壳在 enable 期反射读 `max-players` 注入 `capacity`，`weight` / `metadata` 恒为 0 / 空；服务端 `registry.Register` 是整条覆盖（运行期不可部分刷新），`Report` 刷新 9 个指标字段却**不含** capacity / metadata，`Heartbeat` 只刷 `LastHeartbeat`。
- 既有先例说明「自报事实」这一模式在本仓是成立的：ADR-0024（bc 上报后端归属，控制面只当只读事实）、ADR-0039（agent 自报构建版本）、FR-226（自报工作目录）、FR-228（自报容量与在线人数）——它们与本次的唯一差别是**时机**：那些是"注册时一次"，本决策要的是"运行期可刷新"。

外部接入方（#16）提出的正是后者：节点能在运行期刷新自己声明的容量与自定义键值标签（供接入方**自行解释**其语义，例如放量范围与玩法口径）。这与 §1 的字面「只读暴露 API」冲突，故必须由本 ADR 显式决策，不得在代码里静默违背（`.claude/rules/decision-alignment.md` §2）。

## 决策

### 1. 在「只读」边界内开一个窄写入面

业务插件可声明**它自己节点**的两类事实：① **容量**（capacity）；② **自定义键值标签**（key=value）。

**明确禁止**（不在本次开放范围，且实现上不可达）：改配置、改 zone、写他人（别的 serverId / namespace）。

### 2. 新增 agent 面端点，语义是「声明刷新」而非「注册」

`POST /beacon/v1/agent/declaration`（与 `/report` 同组，继承 `agentTokenMiddleware` 与受信内部标记）：

- **部分刷新**：请求中**缺键 = 不刷新该字段**（照 `reportRequest` 的指针惯例）；`labels` 提供即为**完整声明集**（整体替换，允许空 map 表示清空）。
- **幂等**：重复上报 = 刷新，**不产生第二条记录**（不新增实例、不追加行）。
- **有界**：对齐 FR-227 既有约束——`key ≤ 32` / `value ≤ 128` / 单节点 `≤ 20` 个标签。
- **请求体只认身份与声明**：`namespace` / `serverId` 只用于定位**自己**；身份校验沿用既有中间件与 `serve` 侧「实例须在册」判定，**不信任请求体自报的归属**。

### 3. 两类失败必须可区分

调用方对两类结论的处置完全不同，取值层面分开（沿用本仓既有错误码分面惯例）：

| 结论 | 取值 | 处置 |
|---|---|---|
| **通道不可用** | `401 UNAUTHORIZED`（token 缺 / 错）、`404 NOT_REGISTERED`（尚未挂载数据面 / 实例不在册） | 可重试（退避后重报） |
| **声明被拒** | `400 INVALID_PARAM`（格式非法、超界、键不合法） | 稳定事实，改正后重报 |

agent 侧同构：门面返回**可区分**的结果（`APPLIED` / `REJECTED` / `UNAVAILABLE`），不得用同一个返回值承载两类结论。

### 4. 声明是**只读事实**，不新增任何第二真源

- 控制面**只存不判**：声明**不进入**调度决策、健康打分与发现侧标签过滤的既有真源；`server_tag`（FR-227，控制面权威标签、管理面写、`?tag.*=` 过滤真源）**保持不变**，与「节点自声明」是两个不同事实，本次**不做合并、不做同步**。
- **不碰 zone 权威**：声明里**不含**「我在哪个区」；zone 归属仍由控制面 DB 权威指派（ADR-0004，不变量 §6 不变）。
- 读回：声明生效后可在实例视图读到（admin 与 agent discovery 共用 `toInstanceViews`，字段为既有的 `capacity` / `metadata`），**不新增读端点**。

### 5. 不解释语义

Beacon 只承载"节点声明了哪些 key=value"，**不定义任何 key 的业务含义**（区、玩法模式、放量范围一律由接入方在自己的命名空间下自行解释）。

## 理由

- **性质**：这是"事实类上报"，不是"游戏逻辑进控制面"——控制面不知道 `mode=xxx` 是什么意思，只如实持有并在视图暴露。
- **同源先例**：与 ADR-0024 / 0039 / FR-226 / FR-228 同类，本次只把时机从"注册一次"扩展到"运行期可刷新"，不引入新的架构模式。
- **不改变任何真源归属**：zone 权威（ADR-0004）、标签过滤真源（FR-227 → `server_tag`）、调度与健康真源（ADR-0075 等）全部原样。
- **边界可守护**：把"只读"的例外写成一条**窄**且**可判定**的规则（仅自己的容量与标签），并用负向用例钉住（改 zone / 改配置 / 写他人不可达）。

## 后果

- **正面**：接入方可在运行期刷新自己节点的声明；两类失败可区分，重试语义明确；旧 agent 不下发即缺省（向后兼容，注册时行为逐字不变）。
- **代价**：agent-api 不再是"纯只读门面"，边界靠本 ADR 与 `architecture-invariants.md` §1 的新措辞守护；新增一个 agent 面端点与其测试、文档维护成本。
- **风险与对策**：声明被误当权威（例如被拿来做调度）会形成第二真源——**spec 明文禁止**，并在验收中加"不进入既有真源"的负向断言；声明是内存事实、随注册刷新重建，**不承诺跨重启持久**（与注册/健康同源，符合不变量 §3 的真源切分）。

## 备选方案（已否决）

1. **不开写入口，只让 agent 自身按本地配置刷新**：排除掉了「接入方主动、运行期」这一诉求（改配置需重启 / reload，且业务插件无法程序化触发）。
2. **让 agent 直接写控制面 DB 标签 `server_tag`**：会削弱控制面标签的权威模型与审计边界（该表是管理面写入、`?tag.*=` 的过滤真源），且需要新的鉴权与审计设计——否决。
3. **把声明塞进既有 `/report`**：`report` 的语义是"指标上报"（9 个指标字段 + proxy/backends 指针语义），混入"声明"会让两类语义互相牵制、演进困难——否决。
4. **扩展现有 `Heartbeat` 请求体携带声明**：心跳是高频路径，体量与会话语义都不适合承载声明；且声明变化远低于心跳频率——否决。

## 与既有 ADR / FR 的关系

- **不取代任何 ADR**：ADR-0004（zone 权威）与 ADR-0063 决策 7（**消息门面**的只读与契约稳定，且其 topic 条款已被 ADR-0065 取代）都不受影响；本 ADR 只澄清「agent 对业务插件的 API 面」的一般边界。
- **修订**：`.claude/rules/architecture-invariants.md` §1 的措辞（把"只读"的例外显式写出），并在 `docs/ARCHITECTURE.md` 的 agent 边界处同步一句。
- **增强**：FR-227（标签）、FR-228（容量）——补它们的**运行期**维度；实现并入 **FR-243**。
