# ADR-0087：调度准入作用域读取节点自声明标签（取代 ADR-0086 决策 4 的「不进入调度决策」一条）

**状态**：已接受（决策部分）；实现并入 FR-244，待排期

> 本 ADR **取代 [ADR-0086](0086-agent-self-declaration-narrow-write-surface.md) 决策 4 中「控制面只存不判：声明**不进入**调度决策」那一条**。ADR-0086 的窄写面（决策 1）、端点语义（决策 2）、两类失败可区分（决策 3）、不碰 zone 权威与不新增读端点（决策 4 的其余内容）、不解释 key 语义（决策 5）**全部继续有效、不变**；其决策 4 关于健康打分与发现侧标签过滤真源的部分**同样继续有效**。

## 背景

[ADR-0086](0086-agent-self-declaration-narrow-write-surface.md) 把节点自声明的键值标签定为**只读事实**，并明文写下"控制面只存不判：声明不进入调度决策、健康打分与发现侧标签过滤"。FR-243 落地后，这份标签真源**已经在控制面运行期注册表里**（`registry` 的实例 `Metadata`，由 `POST /beacon/v1/agent/declaration` 写入）。

接入方的诉求随之落地为一个具体问题：调度请求**只认 `zone` / `purpose` / `plugin`**，调用方无法表达"我只要某一类节点"（例如只要某个玩法模式、某一档放量范围）。这些区分**没有第二处可表达**——按 ADR-0086 §5，Beacon 不解释 key 语义，所以"某一类"只能由接入方在**自己声明的标签**上解释；而"声明不进入调度决策"这一条恰好让它**无法被调度读取**。

本仓已有两次同类先例，说明这不是"游戏逻辑进控制面"，而是**判定输入的归属问题**：ADR-0019 的"告警不落库"、ADR-0029 的"值归一化可接受"都曾是被后续需求推翻的单条结论，推翻方式是**新 ADR 取代该条、其余决策不动**（`doc-sync.md` §3）。据此，本次不动 ADR-0086 正文，只取代其决策 4 的一条。

## 决策

### 1. 自声明标签**进入**调度准入判定

调度决策新增**准入作用域**（`admissionScope`）：调用方在 `POST /beacon/v2/agent/schedule/decide` 给出若干备选，每个备选是一组"候选节点**必须自己声明过**"的键值；控制面在**生成候选的那一刻**按它收窄候选。

- 语义：**备选之间 OR、备选之内 AND、逐项精确相等**（不 trim、不折叠大小写；归一化只由写声明的一方做一次）。
- 无约束力即不收窄：缺键 / `null` / 空数组 / 全空备选的退化形态**逐位等同旧行为**。
- 上限对齐 FR-227（`key ≤ 32` / `value ≤ 128` / 单节点 `≤ 20`），并给作用域自身设界（备选 ≤ 8 / 单备选键 ≤ 20）。

判定读的就是 **ADR-0086 决策 2 那个端点写进注册表的那一份**：**只读接入，不新增第二真源**。

### 2. 仍然不进入的健康、排序与过滤（ADR-0086 决策 4 的其余部分不变）

- **不进健康打分**：作用域只是候选门槛，健康分与等级仍是既有真源（FR-147）。
- **不参与候选排序**：候选之间的先后仍是既有 highest_score 契约；作用域只决定"在不在候选里"，不决定"谁排前面"。
- **不进 `?tag.*=` 过滤真源**：发现侧过滤的真源仍是控制面权威标签 `server_tag`（FR-227）；节点自声明与它是两个不同事实，**不合并、不同步**。
- **不新增读端点**：标签随既有候选快照下发（`GET /beacon/v2/agent/schedule/candidates` 的可选键 `labels`），读回面仍是既有的候选 / 实例视图。
- **不新增写面**：ADR-0086 的窄写面仍是唯一写入口；本决策只增加**读**的用途。

### 3. 「判不了」与「确实没有」必须在取值层面分开

标签读取真源**可能未装配**（降级实现 / 快照缺字段）。此时控制面**不得**退化成"忽略作用域照旧决策"（会给出**不符合调用方要求**的结果，且调用方无从察觉），也**不得**报成"没有候选"（那是稳定事实，会误导调用方去改服务范围）。故：

- 服务端：`503 admission_unavailable`（当前状态、可重试）；
- 门面：结论三态 `CHOSEN` / `NO_CANDIDATE`（稳定事实）/ `UNAVAILABLE`（可重试），并**更正**占位实现与降级路径此前把"看不到"印成 `no_candidate` 的取值；
- 候选契约：`labels` **缺键 = 真源未装配**、`{}` = 该节点没声明过标签——两种状态在线上可区分。

### 4. 全部候选都被作用域滤掉时给专属失败码

`failReason = no_candidate_in_scope` **仅当**本次全部候选都因作用域被排除时给出（稳定事实：换服 / 调服务范围才能改口）；"部分作用域排除 + 部分健康排除"仍为 `no_candidate`（健康属**可恢复的当前状态**，不能印成稳定事实）。决策明细的 `excluded` 记 `admission_scope_mismatch`，且**作用域排除先于健康排除**。

## 理由

- **这是"事实类判定输入"，不是"游戏逻辑进控制面"**：Beacon 仍然不知道 `mode=xxx` 是什么意思（ADR-0086 §5 不变），只是把"节点自己声明过的键值"用于**筛选**——与既有 `zone` / `schedulable` / 健康等级同为一类输入。
- **真源仍只有一处**：判定的输入是声明端点写入注册表的那一份，本次**不新建表、不新增写入面、不做双写**；因此不构成 ADR-0086 与不变量 §3 所禁止的"第二真源"。
- **原决策的动机仍然被尊重**：ADR-0086 决策 4 明文的另一半（不进健康打分、不进发现侧过滤真源、不碰 zone 权威）是"声明不得被当成权威标签"的守护，本次**逐条保留**；新增的只是"作为**准入门槛**被读"这一条精确用途。
- **取值可区分是安全要求**：把"判不了"当成"确实没有"会让调用方做出方向相反的处置（改服务范围 vs 退避重试），这也是本仓一贯的错误分面口径（ADR-0086 决策 3 同理）。

## 后果

- **正面**：接入方获得"我只要某一类节点"的可表达契约，且它读的是自己刚声明的真源；判不了 / 确实没有 / 有结果三种结论在服务端与门面两层都可区分；旧调用方（不带 `admissionScope`、不读 `labels`）行为逐位不变。
- **代价**：agent 门面再多一个值对象（`AdmissionScope`）与一个三态枚举（`ScheduleState`）；`decide` / `candidates` 两个线上契约新增键；接入方若以反射读结果并按 `failReason` 字符串分支，需要同步认识新增取值（门面同时给出 `state()` 三态正是为此）。
- **风险与对策**：把作用域当成"标签的权威语义"会越界——本 ADR 与 FR-244 规格把范围钉在**准入门槛**上（不进健康、不参与排序、不进 `?tag.*=` 真源）；"判不了"被静默忽略会给出不符要求的结果——以 503 与三态守护，并在验收中加"绝不忽略作用域照旧决策"的负向断言。

## 备选方案（已否决）

1. **不改 ADR-0086，把作用域放进 `purpose` / `plugin` 的取值约定**：`purpose` / `plugin` 是自由文本标签，不构成可判定契约（既无上限也无相等语义），且会把"业务分类"塞进两个自述字段——否决。
2. **让控制面解释 key 语义（内建"玩法模式 / 放量范围"概念）**：与 ADR-0086 §5 直接冲突，且让 Beacon 承担业务语义的演进责任——否决。
3. **为作用域另建一份标签表 / 索引**：构成第二真源，且要与声明端点双写——违背 ADR-0086 决策 4 与不变量 §3——否决。
4. **判不了时忽略作用域、照旧决策**：调用方会拿到"看起来成功但不符合作用域"的结果而无法察觉——否决（改用 503 + 三态）。
5. **判不了时报 `no_candidate`**：把"当前看不到"印成稳定事实，误导调用方改服务范围——否决。
