# ADR-0090：抓取端点独立监听并支持可选 Bearer 鉴权

**状态**：已接受

> 本 ADR **部分取代 [ADR-0020](0020-prometheus-metrics-observability.md)**：被取代的是「在**自身 HTTP 同端口**暴露 `GET /metrics`」与「与 agent 端点同属内网信任面、**不挂鉴权**」两条约定。
> **承继** ADR-0020 其余全部决策：独立 `*prometheus.Registry`、pull 模型（gauge 抓取时读内存注册表现算、不在运行态写路径埋点）、counter 语义、第三方依赖选型，以及**指标清单本身一个都没变**。
> [ADR-0089](0089-http-layer-red-metrics.md)（HTTP 层 RED 指标）在决策上**不受影响**：它新增的指标、分桶、中间件顺序全部仍然有效；仅其「同端口」这一前置描述随之失效，故该 ADR 的状态行补注指向本 ADR。

## 背景

ADR-0020 决定把 `GET /metrics` 挂在控制面自身 HTTP 端口的根路由上，属「内网信任面、不挂管理台鉴权」。这在当时是合理取舍——该端点只暴露聚合运行指标、不含配置内容与凭据，且省去一个监听器。

但部署默认值与「内网信任」这一前提之间存在落差：

- 控制面默认 `http-addr: ":8848"`。在 Go 网络约定里 `:8848` 表示**绑定所有网卡**（等价 `0.0.0.0:8848` + `[::]:8848`），**不是** `127.0.0.1:8848`。
- `docker-compose.yml` 的端口映射未写宿主 IP，Docker 默认同样绑 `0.0.0.0`。
- 抓取端点在主路由根上注册（只经过 HTTP 指标 / recover / traceId / 访问日志这四个**非鉴权**中间件），管理面鉴权挂在 `/admin/v1` 子树内，覆盖不到它。

三者叠加的结果是：**只要主端口可达，无需任何凭据即可读取该端点**。而它暴露的是 `beacon_instances_registered{namespace,role}` 与 `beacon_instances_status{status}`——即**组织拓扑与容量画像**（有哪些 namespace、各多少实例、健康分布、接口延迟趋势）。这些值不含凭据（ADR-0020 的定性依然正确），但对无授权者而言正是做侦察时会收集的东西。

更关键的是**它无法单独收敛**：抓取端点与承载管理台、agent 数据面、SSE 长连接的业务主端口共用一个监听地址，想限制抓取就必须连带影响业务面，或依赖反向代理按路径分流。

[Prometheus 官方安全模型](https://prometheus.io/docs/operating/security/)对此有明确立场：监控组件的 HTTP 端点「**不应暴露到互联网等公开可达网络**」，并**显式点名 `/metrics`**；同一文档也提醒这些端点「很容易被请求打满乃至 DoS」。

## 决策

把抓取端点从主端口迁到**独立监听地址**，并新增**可选** Bearer 鉴权。

1. **独立监听**：新增配置段 `metrics-endpoint`，字段 `listen-addr`。**默认 `127.0.0.1:8849`**（仅本机回环，外部天然不可达）。
2. **置空即关闭**：`listen-addr` 置空字符串表示**不启动**该端点。
3. **放开须显式**：改为内网 IP（如 `10.0.0.5:8849`）或 `:8849`（所有网卡）即可让外部抓取。放开与否是运维的显式选择，不再是"什么都不做就对外"。
4. **可选鉴权**：新增 `bearer-token`，校验标准 `Authorization: Bearer <token>`。**默认空 = 不鉴权**。该值属敏感项，**仅从环境变量 `BEACON_METRICS_ENDPOINT_BEARER_TOKEN` 注入，不写入库 yaml**（沿用 `git-export.remote-token` 的既有范式）。
5. **路径不变**：仍为 `GET /metrics`。
6. **不加限流**：本批不引入抓取限流。
7. **主端口不再提供** `/metrics`，`server.Handlers.Metrics` 字段随之移除。

配置校验（`validateMetricsEndpoint`）：

- 非空值必须是 `host:port` 形式——裸 IP 会被 `net.Listen` 拒，但那发生在启动后期，提前到校验期报错更可诊断。
- **不得与 `http-addr` 相同**：两者相同则后监听者必然 bind 失败（表现为难定位的 `address already in use`），且语义上等于把抓取端点又挂回业务面——正是本次要消除的形态，故直接拒绝。
- 监听在**非回环**地址且**未设凭据**时记一条 WARN。不禁止（内网可信域部署是正当场景），但要让运维明确知道"任何可达该地址者都能匿名读取运行指标"。

## 理由

- **默认安全优于默认便利**：抓取端点的暴露面应当由运维显式放开，而不是由默认值替他决定。回环默认让"按文档理解成内网信任"的部署不会在不知情时对外暴露——原始问题恰恰是**默认值与文档语义的落差**，而非文档没写警告。
- **独立监听让暴露面可单独收敛**：这是把 `listen-addr` 设为内网 IP、或绑回环后经反向代理分流的共同前提。共用一个监听地址时，任何收敛手段都只能作用于整个业务面。
- **回环默认不牺牲可用性**：同机抓取（Prometheus 与控制面同机）直接把 `127.0.0.1:8849` 写进抓取配置即可；跨机抓取需改一行 `listen-addr`，代价极小且意图明确。
- **Bearer 而非 Basic**：Prometheus 抓取侧原生支持两者（`authorization:` / `basic_auth:`），但 Bearer 是纯 token 语义、天然匹配"一个抓取方一个凭据"，不涉及用户名；且与仓内既有的 `Authorization: Bearer` 管理面令牌习惯一致，运维不必记两套。比较用 `subtle.ConstantTimeCompare`（与 `internal/auth` 的口令校验同款），避免逐字节比较的耗时侧信道。
- **鉴权可选而非强制**：内网同机抓取是最常见形态，强制鉴权会破坏开箱即用；而默认监听地址已是回环，未设凭据时的实际暴露面本就收敛。Grafana（`[metrics] basic_auth_username/password`）与 Gitea（`metrics.Token`）等同类端点均采用"可选加固、默认放行"的形态。
- **不加限流（本批）**：限流属独立关注点（防抓取 DoS），且引入令牌桶需要新的参数与调优判断；本次先解决"暴露面可收敛"这一更根本的问题。抓取端点独立后，即使不放限流，也可由网络层或反代承担该职责。

## 后果

- **破坏性变更**：主端口 `:8848` 不再提供 `/metrics`。既有抓取配置必须改指 `127.0.0.1:8849`（同机）或按实际 `listen-addr` 调整。已在 [OPERATIONS](../OPERATIONS.md) §3.2 与 CHANGELOG 记录。
- **抓取不再被自记**：原先 `/metrics` 挂在主路由上，每次 scrape 会被 HTTP 中间件记进 `beacon_http_requests_total{route="/metrics"}`（[ADR-0089](0089-http-layer-red-metrics.md) 后果节专门提醒过"算业务 QPS 时要剔除它"）。迁到独立监听器后不经主路由中间件链，该自记消失——**这是行为变化，不是缺陷**：抓取流量本就不是业务流量。用该指标算 QPS 的旧口径需相应调整（OPERATIONS §3.2 已同步）。
- **多一个监听器**：进程多一个 `http.Server`，须纳入优雅关停。**自更新 / 回滚分支必须显式关停它**：那两个分支会 spawn 新进程接手同一端口，不先释放则新进程 bind 失败（表现为"更新后抓取端点起不来"）。实现见 `cmd/beacon/main.go` 的 `shutdownAll`。
- **抓取端点绑定失败 = 启动失败**：与主服务同等对待（进 `errCh` 终止进程）。不静默降级——"以为在抓、实际没在抓"会持续到有人发现看板没数据，比直接失败更难排查。
- **非回环 + 无凭据仅告警不阻断**：该组合有正当场景（内网可信域），且是否"可信"本就不是控制面能判定的（取决于防火墙与网段），故只提示不拦截。

## 备选方案

- **保持同端口，仅加 Bearer 鉴权**：最小改动，但暴露面仍与业务面绑定——想收敛抓取就只能动整个业务端口，且默认 `:8848` 全网卡的问题依旧（只是从"匿名可读"变成"需要凭据可读"）。未解决根本问题。否决。
- **保持同端口，改用主端口鉴权（管理面令牌）**：让 Prometheus 持管理台令牌，等于把管理面凭据交给监控系统；且抓取端点会受管理面鉴权/只读裁决/审计链影响，语义错位。否决。
- **独立监听但强制鉴权**：安全上更强，但破坏同机抓取的开箱即用，且需为"本地可信抓取"额外开一条豁免路径（等于又引入一个判断分支）。可选形态已能覆盖：默认回环 + 需要时加凭据。否决。
- **独立监听 + 本批同时加限流**：见"理由"末条——属独立关注点，混入会扩大本次变更面。推迟。
- **仅在反向代理层限制 `/metrics`**：零代码改动，且对既有部署有效。但依赖每个部署都正确配置反代，默认值仍是"全网卡 + 无鉴权"；一旦漏配即暴露。作为纵深防御的一层仍然推荐（OPERATIONS 已提示），但不能替代默认值的修正。否决作为唯一手段。
