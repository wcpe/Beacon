# ADR-0083：入口 / 登录服作为 LobbyCluster 成员，不新增第二落脚真源

**状态**：已接受

## 背景

现网 namespace `prod` 下 `login-1` / `login-2` 是玩家的**登录 / 入口服**，但它们在控制面里与普通子服无区别，且**完全未归属**（无 BC / 大区 / 小区 / 大厅）。运维无法表达"这两台是入口"。

围绕"如何让玩家进入"，本仓已有两层既有结论：

- **ADR-0075（已接受）**：每个 namespace 有且仅有一个 DB 权威 `LobbyCluster`；BC 首次落脚**只**从大厅候选按**共享纯排序契约**（过滤不可调度 → 最高健康分 → 容量占用率低者 → 可注入随机源）选一个；明文约束 **「不新增大厅专属权重、阈值、轮询或全局预留」**；`is_default_entry` / `zoneDefaultEntry` 只表达 **Zone 内业务默认入口**，**不参与**新 BC 首次落脚。ADR-0031 的相关消费链已被它精确取代。
- **FR-200（已交付）**：实现上述落脚，并显式废弃「单入口 priority」作为首落脚真源。

FR-225 初稿要新建「入口服**列表** + **轮询 / ranked**」并让 BC 首次落脚优先取它——这正是 ADR-0075 点名禁止的**第二套落脚真源**，会把刚落地的模型顶掉。

## 决策

### 1. 入口 / 登录服就是 LobbyCluster 成员，不引入新实体与新真源

「入口 / 登录服」不另立层级、不另立列表。它是 **LobbyCluster 的成员**（`server.lobby_cluster_id` 指向该 namespace 唯一大厅集群），经 ADR-0075 决策 2 的**归属迁移 + 排空门 + 原子审计**显式指派。控制面**不新增**任何"入口服列表"作为落脚依据。

前置条件：**入口 / 登录服必须是 `kind=backend`**——ADR-0075 决策 2 的不变量 2 明确「仅同 namespace 的 `kind=backend` 可设 `lobby_cluster_id`」，proxy/BC 恒为 NULL。现网 `login-1` / `login-2` 已是 backend，与本约束一致。

### 2. 多入口分流 = 复用 ADR-0075 的共享排序契约，不新增机制

多台入口（`login-1` / `login-2`）**天然**是同一大厅候选池中的多个成员；分流由既有共享排序契约完成——**不新增大厅专属轮询、权重、阈值或全局预留**（遵 ADR-0075）。控制面在线决定、BC 本地首次决定、断连降级三者共享同一契约不变。

### 3. `is_entry` 展示标记：**本期不做**

若运维确需在拓扑 / 资产上辨识"哪些大厅成员是入口 / 登录服"，可另立 `is_entry bool`（或等价）**纯展示标记**——但**本期不做**。理由：把入口服指派为大厅成员后，"是不是入口"在语义上已与"是不是大厅成员"重合，多一个标记属多余概念。将来确有展示需求时再单独立项评估，届时须遵守同一条约束：**该标记不得进入候选过滤或排序逻辑**（否则即构成第二真源），service 层须保证排序纯函数不读它。

### 4. 不触碰 Zone 默认入口语义

`server.is_default_entry`（Zone 级）与 discovery 的 `zoneDefaultEntry` 兼容字段**保持原样**：[ADR-0067](0067-default-entry-v2-authority.md) 的数据模型 / API / UI 与 ADR-0075 的兼容表达均不改。本 ADR **不新增**它们与首落脚的关系。

## 与既有 ADR 的关系

### 对 ADR-0075 的关系

**不取代、不修订**，而是**在其约束内落地** FR-225：入口服进大厅候选、复用单一调度器、不新增第二真源。ADR-0075 的六条决策与全部不变量继续有效。

### 对 ADR-0031 / ADR-0067 的关系

不新增取代范围。二者在本 ADR 中维持 ADR-0075 已划定的边界。

## 理由

- 保持**单一落脚真源**：ADR-0075 明确"维护第二套大厅缓存或反向指派成员会形成多真源，漂移时无法判定谁正确"。入口服若另立列表，即复现该问题。
- **最小概念增量**：入口服复用既有 LobbyCluster 归属与迁移链路（排空门 / 原子审计 / 互斥字段），不新增表、不新增端点。
- **分流免费获得**：多入口的负载分散由既有共享排序契约（健康分 / 容量 / 随机）覆盖，无需为"入口"再造轮询。

## 后果

### 正面

- `login-1/2` 可被指派为大厅成员，大厅集群随之 `ready`，BC 首次落脚即按既有调度在二者间分流。
- 零第二真源，与 FR-200 / ADR-0075 完全一致，不需要修订 FR-200。

### 约束与迁移

- 需先把 `login-1/2` 从未分配迁移到 LobbyCluster（走既有排空门）。
- 若业务确需区分「入口池 / 常驻大厅池」，属**新决策**，须另开 ADR，不得在本 ADR 内夹带。
- **FR-225 的实施退化为「把 `login-1/2` 指派为大厅成员」**——复用既有指派链路，几乎无新增后端，与待办段 **A1 / A2** 重合。故**实施并入 A1 / A2，不单列开发轨道**；本 ADR 的价值在于**约束未来不得回退到第二落脚真源**。
- ~~`is_entry` 若引入，须有代码级保证其不参与排序~~ → 本期不做（见决策 3）。

## 备选方案

### 方案 A：新建"入口服列表 + 轮询 / ranked"作为 BC 首次落脚真源

与 ADR-0075「不新增大厅专属轮询」「单一真源」直接冲突，会把落地的模型顶掉，并造成双真源漂移。否决。

### 方案 B：把入口服建成与 LobbyCluster 并列的独立层级

须用 ADR 明确取代 ADR-0075 对应部分并同步修订 FR-200，代价大、收益（仅为"名字上区分"）不成比例。否决。

### 方案 C：干脆不做，维持 `login-1/2` 未归属

则运维仍无法把登录服纳入大厅、BC 首次落脚无入口可用。不满足需求。否决。
