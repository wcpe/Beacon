# 功能规格：Agent 上报服务器工作目录

> 状态：已实现（单测通过；跨端 agent 编译通过，真机端到端验收待做）　·　关联 PRD：FR-226（增强 FR-208）　·　分支：feature/agent-server-workdir-report

## 1. 背景与目标

管理台的身份 / 冲突视图目前只显示 `serverId`、`lastAddr`（如 `127.0.0.1:20206`）、`bootId`、注册时间。当多台实例同名或地址相同时，运维**无法分辨"这条绑定对应磁盘上哪个服务器目录"**，排查冲突（如同一 serverId 被两个 bootId 注册）时缺少最关键的锚点。

本 FR 让 agent 上报其所在服务器的**工作目录绝对路径**，控制面存储并回显。属 P3。

## 2. 需求（要什么）

- agent 在**注册**时上报**服务器工作目录绝对路径**（`workDir`）；心跳**可选**携带（省带宽，见 §7）。
- 控制面存储该字段，并在**身份 / 冲突视图**回显，与 `lastAddr` / `serverId` / `bootId` / 注册时间并列（后四项已存在，本 FR 只需前端渲染，见待办段 B2）。
- **兼容降级**：旧版 agent 未上报时该字段为空，视图显示"—"，不报错。

范围内：新协议字段、agent 采集、控制面存储与回显。
不做（范围外）：文件系统浏览 / 远程读写（属 FR-209 审批域）；目录变更的告警。

## 3. 设计（怎么做）

- **协议**：注册 / 心跳请求体新增可选字段 `serverWorkDir`（string，绝对路径）。**只增不改**，向后兼容（遵 ADR-0005 codec 演进）。
- **agent 侧**：`agent-core` 取**配置声明的 server 目录**（比进程 `cwd` 稳定），随**注册**携带；心跳可选携带（与既有 `lastAddr` 同路径）。
- **控制面**：`agent_identity`（或等价表）新增 `server_work_dir` 列；注册 / 心跳写入；列表与详情读取。
- **安全**：目录路径属部署信息、非敏感凭据，**入审计**时按既有脱敏规则处理（路径本身可记）。
- **冲突诊断**：冲突视图展示「目录 + 地址 + bootId」三元组，直接暴露「同 serverId 被两个不同目录注册」。

## 4. UX / 交互

- 用户任务：从冲突条目一键判断是哪台、哪个目录。
- 进入路径：`/identity-conflicts`（身份冲突页）行展开 / 详情抽屉。
- 操作闭环：看到冲突 → 展开详情 → 目录 / 地址 / bootId / 注册时间一目了然 → 判断保留哪一个 bootId。
- 状态设计：旧 agent 无目录 → 显示"—"并提示「该 agent 版本未上报目录」；超长路径省略中段、悬停显示全量。
- IA 挂载：`docs/UX.md` 系统域 `/identity-conflicts`；不新增页面，属页内增强。

## 5. 任务拆分

- [x] 协议：注册 / 心跳新增可选 `serverWorkDir`
- [x] agent-core 采集并携带（含未配置 / 取不到时的空值处理）
- [x] 控制面：`agent_identity` 增列 + 写入 + 读取接口回显
- [x] 前端：冲突 / 身份视图渲染目录（B2）
- [ ] 文档同步：PRD 状态、API、ARCHITECTURE、CHANGELOG

## 6. 验收标准

- 新版 agent 注册后，`GET /admin/v2/agent-identities` 返回 `serverWorkDir` 且等于实际目录。
- 旧版 agent 注册该字段为空 / 省略，接口与前端均不报错。
- 冲突详情页可见 目录 + `lastAddr` + `serverId` + `bootId` + 注册时间 五项。
- **跨端**：Java agent 与 Go 控制面版本错配（新 agent + 旧控制面 / 旧 agent + 新控制面）均不崩、字段安全降级。

## 7. 已确认默认（评审拍板）

- **目录取值口径**：取**配置声明的 server 目录**（比进程 `cwd` 更稳定）。
- **上报频度**：**注册时上报一次**，心跳**可选**携带（省带宽）。
- **隐私**：路径按**既有脱敏规则入审计**。
