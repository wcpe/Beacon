# 功能规格：管理台中间件高密度运维视觉重构

> 状态：开发中　·　关联 PRD：FR-137

## 1. 背景与目标

现有管理台已经完成 shadcn-ui 接入、两层页眉、卡片降级、列表页密集表格和 UI 包抽取，但近期原型评审后确认当前视觉方向仍不符合目标：不要 Minecraft 地图 / NOC 大屏 / 游戏风装饰，而是要更像中间件后台的简洁、高密度、可连续扫读的运维控制台。

本 FR 属 P2，目标是按已确认的“简洁中间件后台 + 高密度信息卡片 + 裸表格”设计稿，重做首页和核心页面视觉组织，优先覆盖五个入口：可观测看板、文件同步、服务器、区分配、集群拓扑。范围为纯前端视觉与交互组织调整，不改变后端 API、agent、文件同步任务模型或发布语义。

## 2. 需求（要什么）

范围内：

- 全局视觉方向：
    - 白底 / 浅灰底为主，使用冷灰边框、低饱和蓝色主操作和语义状态色；保留暗色主题可用。
    - 高密度信息卡片只承载关键指标和对象摘要，不把整段页面再包成大 Card。
    - 页面正文采用紧凑工具栏、细线分区、裸表格、状态点、徽标和小号指标组，减少营销式留白。
    - 保持中间件后台气质，不使用 Minecraft 地图、像素风、地底图、游戏化装饰、NOC 大屏风格或大面积渐变。
- 覆盖页面：
    - 可观测看板 `/dashboard`：调整为一屏优先扫状态的首页，顶部为紧凑 KPI 网格，中部为集群矩阵 / 实时任务 / 最近异常，底部为服务器明细裸表格。
    - 文件同步 `/file-sync`：按“配置区 + 目标筛选 + 执行状态 + 日志 / 明细”重新排布，1000+ 服务器选择必须以搜索、批量勾选、分组和分页 / 窗口化渲染保持可操作。
    - 服务器 `/servers`：保留 FR-106 裸密表范式，强化筛选条、汇总条、行状态可扫读和横向滚动下的列稳定性。
    - 区分配 `/zones`：按已确认设计稿改为过滤条 + 指标条 + 大区/小区树、容量矩阵、右侧详情、底部改派队列的一屏工作台；中间矩阵无操作列，点击行切换详情。
    - 集群拓扑 `/topology`：按已确认设计稿改为过滤条 + 指标条 + 左侧图层、中心拓扑画布、右侧节点诊断、底部异常链路表的一屏工作台。
- 组件边界：
    - 通用、无 Beacon 业务依赖的展示组件优先放入 `web/packages/ui` 并同步 wiki 展示；业务壳和页面编排仍留在 `web/src`。
    - 不新增第三方依赖；继续复用 React、Tailwind v4、shadcn/Radix、lucide 与现有 UI 包。
- 文案：
    - 新增可见文案必须进入 `web/src/i18n/locales/zh-CN.ts`，页面不新增硬编码中文。

不做（范围外）：

- 不改后端 API、数据库 schema、agent 行为、SSE 协议或文件同步执行语义。
- 不重新设计导航信息架构，不新增 / 删除路由。
- 不引入 Storybook、可视化回归平台、虚拟滚动新依赖或新的图表库。
- 不一口气重做所有后台页面；非五个核心页面只继承全局 token / 组件变化，不做逐页返工。
- 不取代 ADR-0012 / ADR-0059：仍使用 shadcn-ui + Tailwind v4 与内部 UI 包，不做重主题化或外部设计系统迁移。

## 3. 设计（怎么做）

仅前端改造，无新增 ADR。该 FR 是对 ADR-0012 的页面级视觉收敛：保留 neutral/shadcn 技术路线，只在页面布局、密度、间距、边框、状态表达上统一到已确认的中间件后台风格。

- 全局样式：
    - 在现有 Tailwind token 基础上收敛内容区背景、分隔线、表格行高、工具栏高度和指标卡尺寸。
    - Card 仅保留给单条对象、弹层、可点击磁贴；区段继续用 `SectionHeader` + 细线 / 留白。
- 通用组件候选：
    - `MetricGrid` / `MetricTile`：紧凑指标组，支持语义 tone、图标、数值、辅助说明。
    - `DenseToolbar`：单行 / 自动换行的筛选工具栏，统一控件高度和间距。
    - `StatusDot` / `StatusPill`：用于表格和日志的轻量状态表达。
    - 进入 UI 包前必须确认不依赖 Beacon API、路由、auth、环境状态或业务 i18n key；否则保留在页面本地。
- `/dashboard`：
    - 首页顶部展示系统关键态：实例健康、Agent 连接率、SSE、配置发布、文件同步、命令队列、告警、API 延迟、任务积压、存储、缓存、熔断、回滚。
    - 中部展示集群健康矩阵、实时任务、最近异常三块可扫读面板。
    - 底部展示服务器明细表格，长列表仅表格内部滚动，不再把状态墙 / 趋势作为首屏主体。
- `/file-sync`：
    - 顶部配置区压成两行以内：源服、目录、批次大小、间隔、熔断阈值、主操作。
    - 目标筛选改为“分组统计 + 搜索 + 已选 / 剔除摘要 + 表格窗口”，避免 1000+ checkbox 一次性铺满。
    - 运行态区域强调当前批次、成功 / 失败 / 处理中、熔断告警、暂停 / 继续 / 终止按钮。
    - 日志终端和服务器明细并排，窄屏改上下排列。
- `/servers`：
    - 延续现有 `DataTable`、分页和详情 Sheet，优化表头密度、筛选条和状态列可读性。
    - 不改变下线、drain、改派、重同步、日志入口。
- `/zones`：
    - 左侧大区 / 小区树、中心容量矩阵、右侧分配详情均采用内部滚动。
    - 中心容量矩阵移除操作列；点击或键盘 Enter / Space 选择行并刷新右侧详情。
- `/topology`：
    - 拓扑画布与异常链路表共处一屏，画布不产生页面级深滚。
    - 节点选择更新右侧诊断，异常链路表保留底部内部滚动。

## 5. 验收标准

- 五个页面符合已确认设计方向：简洁中间件后台、高密度信息卡片、裸表格 / 细线分区，无 Minecraft / 地图 / NOC / 游戏化装饰。
- `/dashboard`、`/file-sync`、`/servers`、`/zones`、`/topology` 在约 1920×1080、浏览器 100% 缩放下首屏可完成主要运维操作；长列表只在表格 / 树 / 日志等内部区域滚动。
- `/file-sync` 在 mock 1000+ 服务器数据下仍可搜索、批量选择、剔除、查看已选摘要，页面不出现明显卡顿或不可操作的超长 checkbox 列表。
- 页面原有业务行为不回归：Dashboard 查询、文件同步 SSE 与控制按钮、服务器行操作与详情面板、区分配安全改派、拓扑节点选择保持。
- 新通用组件若进入 `web/packages/ui`，ui-wiki 有对应展示或明确说明。
- 无新增第三方依赖；可见文案均走 zh-CN i18n。
- `cd web && pnpm test`、`pnpm build` 通过；改动含 UI 包时同步跑 UI 包 / wiki 构建。
- 用浏览器验证桌面与窄屏主要视图，截图与已确认设计稿方向一致。

## 6. 风险 / 待定

- 截图验收若某页仍超出 1920×1080，需要优先压缩行高 / 区块高度，不扩大范围到其他路由。
- 1000+ 服务器目标选择第一版不新增虚拟滚动依赖，只能基于分页 / 限量窗口 / 搜索减少 DOM；若仍不足，再单独评估依赖引入。
- 若实现中需要显著修改全局 token 或推翻 ADR-0012 “默认 neutral、不做品牌化定制”，必须先补新 ADR 并再次确认。
