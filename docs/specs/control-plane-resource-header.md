# 功能规格：控制面资源页眉显示

> 状态：开发中（实现与 CHANGELOG 均已完成，尚未随任何版本发布，故不标已交付）　·　关联 PRD：FR-272　·　版本线：未发布　·　分支：rc-candidate-identity

## 1. 背景与目标

页眉已收敛为单层，控制面状态点与环境筛选之间留有空间。运维人员需要一眼观察控制面进程 CPU 与 Go 堆内存占用，快速判断当前运行负载；本项只补充页眉资源摘要，不改变既有页眉结构。

## 2. 需求（要什么）

- 页眉直接显示控制面进程 CPU 占比与 Go 堆内存用量。
- CPU 与内存均反映控制面进程。
- 资源摘要仅占页眉现有空白区域；窄屏隐藏，不引入新依赖。
- 加载中或首次请求失败时显示占位符；轮询失败保留最后一次成功值；单项采样不可用不影响其它指标。
- 不合并进控制面状态点的全局运维指标弹层，后者继续承载 Agent、待确认、告警与变更单指标。

## 3. 设计（怎么做）

- 后端沿用既有 `GET /admin/v1/system/status` 响应中的进程 CPU 字段及 Go runtime 堆内存字段；无数据库或持久化变化。
- CPU 由 `gopsutil/v4/process` 采集控制面进程占比，内存展示 `runtime.heapAlloc / runtime.heapSys`。前端通过独立 TanStack Query hook 每 8 秒请求状态端点，不与 `useGlobalOpsMetrics` 混合。
- 资源指示器位于环境筛选器与右侧工具区之间，宽约 200–260px，`lg` 以下隐藏；CPU 与堆使用率超过 80% 使用警告色；堆内存按 B / KB / MB / GB 自适应格式化。
- 资源组 tooltip 简短说明「控制面进程 CPU 与堆内存占用」。

## 4. UX / 交互

- 用户任务：在任一管理台页面顶部快速查看控制面当前运行负载。
- 进入路径：全站单层页眉常驻显示；不新增路由或页面。
- 状态设计：无数据 / 首次请求失败显示「—」；单项不可用单独显示「—」；轮询失败保留上次成功数据，避免闪烁。
- 响应式：`lg` 以下隐藏，不挤压窄屏页眉；桌面页眉保持原有单层布局。

## 6. 验收标准

- 后端 status、handler 与 TypeScript 契约保留 `cpuAvailable` / `cpuPercent` 及 Go 堆内存字段。
- 页眉展示进程 CPU 与堆内存；CPU / 堆使用率大于 80% 呈警；堆内存单位自适应；不可用为「—」。
- 资源数据每 8 秒独立轮询；首次失败显示占位符，后续失败保留最后一次成功值。
- `lg` 以下隐藏；中英文标签和进程口径提示正确；既有状态点弹层保持原样。
- 用户指定的 Go build / 测试及 Web typecheck / lint / test 通过。
