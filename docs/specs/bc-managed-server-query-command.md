# 功能规格：BC 受管服务器查询命令（FR-202）

> 状态：草拟　·　关联 PRD：FR-202　·　分支：待执行时创建

## 1. 背景与目标

FR-200 让 BC 持有当前 namespace 的 Beacon 受管服务器目录和大厅候选快照，但现有本地 `/beacon status` 只展示 Agent 生命周期、连接、配置 md5、心跳周期与控制面 endpoint，无法回答“BC 当前到底注册了哪些 Beacon 服务器、某台为什么不可调度、最近一次目录同步是否成功”。运维只能翻日志或进入管理台，现场排障链路过长。

本功能只为 BC/Bungee Agent 补充本地只读命令：分页查看受管目录摘要、按 serverId 查看单服详情，并在既有 `status` 后追加目录同步与大厅候选摘要。所有查询只读取 FR-200 已原子发布的内存快照，不访问控制面、不读本地缓存文件、不触发同步，也不改变 Bukkit Agent 的命令集合。

## 2. 需求（要什么）

### 2.1 范围内

- `/beacon servers [页码]`：分页展示 Beacon 实际注入本 BC 的受管服务器摘要；页码缺省为 1，每页固定 10 条，不提供 pageSize 参数。
- `/beacon server <serverId>`：精确查询一台受管服务器详情。
- 目录摘要与详情展示：目录来源、LobbyCluster/大区/小区归属、在线状态、健康状态、是否可调度；详情额外展示全部不可调度原因。
- BC 的 `/beacon status` 在现有内容后追加：目录是否已完成首次同步、最近一次成功同步时间、受管服务器总数、大厅候选总数与可调度数。
- 所有回显、帮助、错参、越界页码、未知 serverId 和尚未同步提示使用中文。
- 命令沿用根权限 `beacon.admin`；未授权调用由平台权限系统拒绝，不提供绕过权限的别名。
- 一次命令执行只捕获一份不可变内存快照，保证页数、总数和行内容来自同一版本。

### 2.2 明确不做

- 不查询 Bungee 中手工配置、非 Beacon 管理的服务器；“受管服务器”只指 FR-200 当前生效快照中的目录项。
- 不从控制面实时查询，不读最后有效缓存文件，不扫描 Bungee 配置或运行时服务器注册表，不因查询命令触发重同步。
- 不在命令中增加重同步、改 LobbyCluster、设默认服、切服、踢人或调度写操作。
- 不展示玩家名单、token、认证头、完整错误堆栈或其他敏感信息。
- 不为 Bukkit Agent 注册 `servers` / `server`，也不让 Bukkit 的 help/status 出现 BC 专属字段。
- 不提供无界全量输出、可配置页大小、模糊搜索、排序参数或导出功能。
- 不新增第三方依赖，不另建持久化查询模型。

## 3. 命令与输出契约

### 3.1 权限、解析与分页

| 命令 | 权限 | 参数 | 行为 |
|---|---|---|---|
| `/beacon servers` | `beacon.admin` | 无 | 等价于第 1 页 |
| `/beacon servers <page>` | `beacon.admin` | 十进制正整数 | 返回指定页，每页固定 10 条 |
| `/beacon server <serverId>` | `beacon.admin` | 非空、精确匹配 | 返回单服详情 |
| `/beacon status` | `beacon.admin` | 无 | 保留现有输出并追加 BC 目录摘要 |

解析规则：

- `page` 非整数或小于 1：回复“页码必须是大于等于 1 的整数”，附正确用法，不读取目录。
- 目录为空时，第 1 页返回明确空态；任何大于 1 的页码返回“页码超出范围，当前共 0 页”。
- 非空目录中 `page > totalPages`：回复“页码超出范围，当前共 N 页”，不自动回退到最后一页，避免误认所查页存在。
- `serverId` 去除首尾空白后必须非空，按大小写敏感精确匹配；未知值回复“未找到 Beacon 受管服务器：<serverId>”。回显前过滤控制字符并限制长度，防止恶意标识污染控制台。
- 多余参数和未知子命令继续进入统一中文错参帮助，不静默忽略。

稳定排序与分页：

1. LobbyCluster 成员在前，按 serverId 升序；大厅集群在 namespace 内唯一，不引入额外名称排序。
2. 普通区服随后，按大区名、小区名、serverId 升序。
3. 无有效拓扑归属的受管项最后，按 serverId 升序。
4. 对排序后的扁平列表按固定 10 条切页；同一页按实际条目输出对应分组标题，不为本页没有的分组输出空标题。

### 3.2 `/beacon servers [页码]` 输出

首行固定摘要：

```text
Beacon 受管服务器：第 <page>/<totalPages> 页，共 <total> 台，每页 10 台；最近同步=<UTC ISO-8601 或“尚未成功同步”>
```

每条固定一行，字段顺序稳定：

```text
  <serverId>｜归属=<全局大厅 / <regionName>/<zoneName> / 未分配>｜在线=<onlineState>｜健康=<healthStatus>｜可调度=<是/否>
```

目录为空时只输出：

```text
Beacon 受管服务器：当前目录为空；最近同步=<UTC ISO-8601 或“尚未成功同步”>
```

命令不得输出 Bungee 手工服务器，也不得为取得展示字段二次查询控制面。`total`、`totalPages`、最近同步时间和本页条目必须来自同一份快照。

### 3.3 `/beacon server <serverId>` 输出

详情固定使用多行中文键值：

```text
Beacon 受管服务器详情：<serverId>
  目录来源=Beacon
  拓扑归属=<全局大厅 / 大区:<regionName>，小区:<zoneName> / 未分配>
  在线状态=<onlineState>
  健康状态=<healthStatus>
  可调度=<是/否>
  不可调度原因=<中文原因列表 / 无>
  目录快照=<snapshotVersion>
```

不可调度原因的机器码由 FR-200/既有调度域提供，命令层只通过单一映射表渲染中文；未知原因码显示“未知原因（<code>）”，不能吞掉。多个原因按调度域给定的稳定优先级输出，使用“、”连接。

### 3.4 `/beacon status` 追加摘要

BC 现有 status 行保持原顺序与语义，在末尾追加：

```text
  受管目录=<已同步/未同步>
  最近成功同步=<UTC ISO-8601 / 尚未成功同步>
  受管服务器=<managedCount> 台
  大厅候选=<schedulableLobbyCount>/<totalLobbyCount> 台可调度
```

“已同步”只表示至少成功应用过一份 FR-200 权威快照，不等于控制面当前可达；控制面断连但仍使用最后有效快照时继续显示最近成功同步时间，不伪造为刚同步。大厅候选摘要只统计 LobbyCluster 成员，不把普通区服或小区默认入口算入。

### 3.5 错误与空态文案

| 场景 | 中文响应要求 |
|---|---|
| 尚未完成首次同步 | 明示“受管目录尚未完成首次同步”，servers 返回空态，server 查询返回暂不可查；不得访问控制面补查 |
| 目录已同步但为空 | 明示“当前目录为空”，与“尚未同步”区分 |
| 非法/越界页码 | 明示参数问题与当前总页数，并附 `/beacon servers [页码]` 用法 |
| 未知 serverId | 明示未找到该 Beacon 受管服务器，不回退模糊匹配 |
| 快照读取异常 | 返回“读取受管目录快照失败，请查看控制台日志”，日志使用中文 ERROR 且不含敏感字段；正常并发更新不得产生此错误 |
| 无权限 | 由平台权限系统按 `beacon.admin` 拒绝；命令逻辑不得泄露任何目录摘要 |

## 4. Agent 设计与并发

### 4.1 内存只读视图

- FR-200 的目录同步组件提供不可变 `ManagedDirectorySnapshot` 只读视图，至少包含：快照版本、最近成功同步时间、是否完成首次同步、稳定排序所需拓扑字段、在线/健康/可调度状态及原因、大厅候选汇总。
- 查询命令在开始时原子取得一次快照引用，随后只在该对象上排序、分页和渲染；同步线程发布新快照不影响正在输出的命令。
- 命令不得持有可变目录集合，不得逐行加锁，不得在循环内访问网络、磁盘或 Bungee 注册 API；1000+ 条目只做一次内存排序和最多 10 条渲染。
- 快照内部按 serverId 建只读索引，单服查询为 O(1)；列表排序结果由快照构建时预计算或在命令调用时一次完成，不允许 N+1 外部调用。

### 4.2 core 与 Bungee 壳层职责

- Agent core 提供平台无关的查询值对象和中文渲染器，输入为不可变快照，输出为字符串列表；不依赖 TabooLib/Bungee 类型。
- Bungee 壳层只负责注册 `servers` / `server`、校验根权限、取得参数、调用渲染器并发送结果；沿用现有异步执行约定，不阻塞代理主线程。
- 既有公共 `OpsCommandText` 增加“按角色追加子命令清单”的最小能力：Bungee help/usage 在共享命令后追加 `servers` / `server`，Bukkit 传空扩展并保持现有清单不变。帮助内容仍由一处清单派生，禁止在壳层复制两套用法文案。
- BC status 通过角色专用组合器把既有 `LifecycleSnapshot` 行与目录摘要行拼接；不得把 BC 字段塞进 Bukkit 的生命周期快照。
- 所有生产日志和错误提示使用中文；纯查询成功不刷 INFO 日志，只有快照不变量异常才记 ERROR，避免每次命令刷屏。

### 4.3 数据边界与安全

- 命令输出只消费 BC 内存中的 Beacon 受管快照；目录来源固定为 `Beacon`，不接受调用方提供 namespace 或其他过滤条件。
- serverId、拓扑名称和原因码均视为外部数据，渲染前去除换行/控制字符并限制单字段长度；超长值截断并加省略号。
- 不输出 token、控制面请求头、监听地址、完整异常、玩家信息或缓存文件路径。
- 本地命令不产生管理审计；Minecraft/Bungee 命令权限与控制台日志是本地边界。若未来要求远程查询或持久审计，应另立 FR，不在本功能中暗加上传行为。

## 7. 验收标准

### 7.1 自动化验收

1. `servers` 缺省页为 1，每页严格 10 条；10/11/1001 条目录分别得到 1/2/101 页，输出条数、总数和页数准确。
2. 排序严格按“大厅 → 大区/小区 → 未分配”及各级名称/serverId 稳定升序；分页前后不重复、不遗漏。
3. 非法页码、越界页码、空目录、尚未同步、未知 serverId 均返回 §3.5 约定的中文提示；不得抛异常或触发网络/磁盘调用。
4. 单服详情准确显示目录来源、拓扑归属、在线、健康、可调度与全部不可调度原因；未知原因码不被吞掉。
5. BC status 保留原有全部行并追加最近成功同步时间、受管服务器数、大厅候选可调度/总数；断连使用缓存时不伪造新同步时间。
6. 同步线程并发发布快照期间，100 个并发查询各自只观察一个完整 snapshotVersion，不出现总数与本页内容混版、并发修改异常或锁住同步线程。
7. Bungee help/usage 含 `servers [页码]` 与 `server <serverId>`；Bukkit 的 literal、help、usage 和 status 与修改前一致。
8. 无权限调用在进入查询逻辑前被 `beacon.admin` 拒绝；输出及日志不含 token、监听地址、请求头、玩家数据和完整异常。
9. Agent core 单测、静态检查和 Bukkit/Bungee 全量构建全部通过，且未执行 `gradle --stop`。

### 7.2 真实 BC 验收（RC 阻断）

在已确认的真实环境（至少 1 个 BC、2 个大厅服、1 个普通区服）执行：

1. `/beacon servers` 能看到全部 Beacon 受管目录，2 个大厅服归入 LobbyCluster，普通区服归入对应大区/小区；手工非 Beacon 服务器不出现。
2. 人为构造超过 10 台受管服务器，验证第 1/2 页边界、非法页码和越界页码中文提示。
3. `/beacon server <serverId>` 对健康大厅、不可调度大厅和普通区服分别显示准确状态与原因；未知 serverId 明确提示未找到。
4. `/beacon status` 展示最近同步、总数和大厅候选摘要；控制面断连后仍显示最后有效快照时间，不触发联网查询。
5. 在目录自动同步或 FR-201 立即重同步同时连续查询，命令响应稳定，BC 主线程无明显阻塞，玩家首次进入与业务插件后续切服不受影响。
6. 使用无权限账号执行三个查询入口均被拒绝，未泄露目录摘要。

以上任一项缺少当前证据，FR-202 不得标记交付，首个 `v1.0.0-rc.N` 不得放行。

## 8. 风险 / 已拍板决定

### 8.1 已拍板

1. `/beacon servers [页码]` 分页查询摘要，固定每页 10 条；不允许无界全量输出。
2. `/beacon server <serverId>` 查询单服详情。
3. 只查询 Beacon 注入 BC 的受管目录，展示大厅/大区/小区归属、在线、健康和可调度状态。
4. 既有 status 增加最近同步时间、受管服务器数量与大厅候选摘要。
5. 所有查询只读内存快照，不触发控制面请求、缓存文件读取或重同步。

### 8.2 风险

- FR-200 若未把展示所需状态与原因纳入原子快照，命令层容易产生二次查询或双真源；必须在 FR-200 边界补齐，不在 FR-202 另算健康/调度。
- 当前公共帮助清单默认双端对称；实现角色化扩展时必须用漂移测试锁住 Bukkit 不出现 BC 专属命令。
- 1000+ 目录每次重新排序可能造成不必要开销；优先由不可变快照携带稳定排序视图，但不要为此引入缓存框架或新依赖。
