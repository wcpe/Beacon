# 前端交互规范（防交互漂移）

> 依据 `docs/UX.md`（前端交互真源）。第一版教训：交互无真源、页面跟着后端能力长、代码写完才第一次看到 UI → 真机否决返工。本规则约束第二版一切带页面的变更。

## 1. UX.md 是前端交互真源（强制）

- 导航 IA、页面清单、页面唯一职责、全局交互契约以 `docs/UX.md` §2/§4 为准。
- 新增页面、变更导航归属、变更全局交互范式，必须**同 PR 更新 UX.md**（与 doc-sync 同级要求）。
- 每个页面唯一职责；说不清职责或与既有页面重叠 → 先改 UX.md（经确认）再动代码，禁止代码先行。

## 2. 带页面的 FR spec 必填 UX 段（强制）

- spec 模板中的「UX / 交互」段对带页面的 FR 必填：用户任务、进入路径、操作闭环、状态设计（空 / 加载 / 错误 / 超大数据量）、IA 挂载位。
- 填不出来 = 页面职责没想清，不开工。纯后端 FR 删除该段。

## 3. mockup 评审门（强制）

- **新页面**或**页面结构性大改**（改布局骨架、改操作主流程、改导航归属）：先在 demo / mock 模式做出可点击的 mock 页面，**经用户浏览器评审拍板后**才接真后端。
- **小改豁免**：在既有页面加按钮、加列、加字段等非结构性变化不强制过门，但仍受 UX 段与全局契约约束。
- mock 数据须覆盖空态 / 常规 / 超大量 / 异常四形态，评审时可切换（复用演示模式 FR-159）。

## 4. 与现有规则的关系

- `error-surfacing.md` 管错误怎么展示；本规则管交互结构与评审流程门。
- `testing-and-quality.md` 的前端测试门（vitest / Playwright）照旧，不因过了 mockup 门而豁免。
- Legacy 维护态页面（FR-138）冻结不改，不受本规则约束。
